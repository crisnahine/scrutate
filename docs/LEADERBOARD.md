## Engine A and structural search: macos-arm64, warm cache

- Hardware: Apple M3 Pro (11 logical CPUs; 5 performance + 6 efficiency cores), 18 GB RAM; macOS-27.2.1-arm64-arm-64bit
- Method: hyperfine (`hyperfine 2.0.0`), output piped, 30 timed runs for scrutate and every contender in 3 interleaved blocks (1 warm-up run per block), warm cache; each block first waits a bounded time for the 1-minute load average to fall below 40.
- Load average (1 minute) at the start of each measured block: median 4.7, max 13.6 on 11 logical CPUs. The machine was shared with other work throughout, so no result here is a publishable #1 claim (section 14 requires dedicated idle hardware); rows whose load exceeded the CPU count carry it in the status column.
- The read-files ceiling (`bench/rawread.c`) is measured once per file set, before that set's first benchmark, and is the fastest of several thread counts: one per CPU and half as many with a warm cache, up to 96 with a cold one (a disk takes more reads at once than there are cores). On a shared machine a row measured later under heavier load can read PARTIAL where a quieter run reads BLOCKED; PARTIAL is the weaker of the two claims.
- A benchmark where some tool's block medians differed by more than 25% was measured while the machine did something else. Each such benchmark was measured again, once, whatever its status (`leaderboard.py --redo-unstable`); its status column gives the first measurement too. A second measurement reflects the machine as it was by then.
- Tool versions: scrutate: `scrutate 0.1.0`; ripgrep: `ripgrep 15.2.0`; ugrep: `ugrep 7.8.5 aarch64-apple-darwin27.0.0 +neon/AArch64; -P:pcre2jit; -z:zlib,bzip2,lzma,lz4,zstd,brotli,7z,tar/pax/cpio/zip`; GNU grep: `ggrep (GNU grep) 3.12`; git grep: `git version 2.56.0`; ag: `ag version 2.2.0`; ack: `ack v3.10.0 (standalone version)`; ast-grep: `ast-grep 0.51.1`.

On a shared machine a row measured later under heavier load can read PARTIAL where a quieter run reads BLOCKED; PARTIAL is the weaker of the two claims.
