# Language capability registry (verified)

Generated by `tools/gen_languages_md.py` from the binary's registry and the snapshot tests; regenerate after changing `crates/scrutate/src/langs.rs`.

## Tiers

1. **Grammar** (tree-sitter): definitions with kinds, qualified names, signatures, documentation, call edges and imports as listed per language below. Every row with a sample file is re-verified by `cargo test` (`tests/samples.rs` compares the parse of `tests/samples/<file>` with `expected.json`).
2. **Heuristic**: languages without a grammar in this build get keyword-introduced definitions (`def`, `fn`, `function`, `sub`, `proc`, `class`, `struct`, `module`, Lisp `(def…`, SQL `CREATE …`, shell `name() {`) with the indented block below them. No call edges or imports.
3. **Windows**: every other readable text file is indexed as overlapping 50-line windows, so it is searchable by Engine B (and, always, by Engine A).

Engine A (instant search) needs none of this: it searches every readable file of any language or no language.

## Optional grammars (`--features extra-langs`, +~80 MB of parse tables)

Fortran, OCaml, F#, Verilog, VHDL, CUDA, TLA+, D, AutoHotkey, Odin, QML, LLVM IR. They compile and parse; they have **no** snapshot samples yet, so their definition extraction is *not verified* and they are off by default.

## Known limits

- Heuristic-tier languages get no call graph, no imports and approximate block extents.
- Nesting depth of data keys (JSON/YAML/TOML) is capped at two levels.
- Grammars that mis-parse unusual syntax fall back to the module header plus windows for that file (never to invented symbols).
